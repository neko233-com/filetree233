# 扫描性能测量

`filetree233 bench PATH --engine walk --threads 4 --iterations 3` 为每次扫描启动独立进程，输出扫描耗时、进程总耗时、峰值工作集（Windows）或峰值 RSS（Linux/macOS）、实际引擎和结果完整性。系统缓存不会被清理；磁盘、文件数量、目录结构和后台进程都会影响结果。可使用 `--engine mft` 测量具备权限的 Windows NTFS 卷；`--engine auto` 会报告实际引擎与回退原因。此命令只扫描，不清理。

以下是一次本机观察，用于验证基准工具与建立起点，不是性能承诺或 WizTree 对比：

- 环境：Windows，AMD Ryzen 9 9950X，Rust 1.99.1；release 构建；2026-11-02。
- 数据：本地 NTFS 测试目录，80 个子目录、8,000 个各 21 字节的文件。三次独立运行，文件系统缓存未清理。
- 普通遍历扫描耗时中位数：1 线程 127.6 ms，4 线程 46.4 ms，8 线程 33.6 ms；8 线程峰值工作集约 10.6 MiB。
- 一次已有依赖缓存的 `cargo build --release --locked` 耗时 13.49 s，生成的 Windows 程序约 6.27 MiB；这不是全新环境的构建时间。
- 尚未测量真实大盘、冷缓存、MFT 与 WizTree 的同机比较；本机进程无管理员权限，无法用该进程读取卷 MFT。

结果会随代码、硬件、缓存和系统负载变化。对新数据集请记录系统、CPU、存储、文件与目录数量、引擎、线程数、完整性及所有单次结果，并单独报告是否为冷缓存。不要通过清理生产缓存来制造冷缓存测试。
