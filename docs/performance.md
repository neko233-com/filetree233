# 扫描性能测量

`filetree233 bench PATH --engine walk --threads 4 --iterations 3` 为每次扫描启动独立进程，输出扫描耗时、进程总耗时、峰值工作集（Windows）或峰值 RSS（Linux/macOS）、实际引擎和结果完整性。`requested_threads` 是用户请求数，`scan_threads` 是实际扫描线程数；MFT 通过有界分块并行读取并按记录顺序合并。系统缓存不会被清理；磁盘、文件数量、目录结构和后台进程都会影响结果。可使用 `--engine mft` 测量具备权限的 Windows NTFS 卷；`--engine auto` 会报告实际引擎与回退原因。此命令只扫描，不清理。

以下是一次本机观察，用于验证基准工具与建立起点，不是性能承诺或 WizTree 对比：

- 环境：Windows，AMD Ryzen 9 9950X，Rust 1.99.1；release 构建；2026-11-02。
- 数据：本地 NTFS 测试目录，80 个子目录、8,000 个各 21 字节的文件。三次独立运行，文件系统缓存未清理。
- 普通遍历扫描耗时中位数：1 线程 127.6 ms，4 线程 46.4 ms，8 线程 33.6 ms；8 线程峰值工作集约 10.6 MiB。
- 以上扫描数字来自移除 GUI 之前的版本，不能代表当前 CLI 版本。

同机移除 GUI 前后的 release 可执行文件分别为 8,218,624 字节和 3,318,784 字节（减少约 59.6%）。两次均有依赖缓存、需要重新编译应用的构建分别为 12.68 秒和 9.99 秒；构建缓存和系统状态不同，不代表冷构建或其他平台。移除后同一 8,000 文件目录、4 线程热缓存测试扫描中位数为 104.0 ms，三次峰值工作集约 9.5–9.6 MiB；移除前本次同条件中位数为 95.5 ms，峰值约 10.3–10.5 MiB。样本很小，不能据此认定扫描速度的变化。
- 尚未测量真实大盘、冷缓存、MFT 与 WizTree 的同机比较；本机进程无管理员权限，无法用该进程读取卷 MFT。

结果会随代码、硬件、缓存和系统负载变化。对新数据集请记录系统、CPU、存储、文件与目录数量、引擎、线程数、完整性及所有单次结果，并单独报告是否为冷缓存。不要通过清理生产缓存来制造冷缓存测试。

## MFT 索引的合成基准

运行 `cargo test --release --locked --bin filetree233 benchmark_snapshot_index -- --ignored --nocapture` 可重复测量目录索引处理：生成 1,000 个范围内目录、50,000 个范围外目录（其共同祖先深 64 层）和 20,000 条文件链接，其中一半位于扫描范围内。

2026-11-02 在上述 Windows / Ryzen 9 9950X 环境各运行一次：优化前目录索引 164 ms、完整处理 173 ms；优化后分别为 5 ms、10 ms。两次均得到 11,001 个树节点。该基准只测内存中的索引逻辑，**不包括读取 MFT、文件系统 I/O 或大盘真实扫描**，也不能据此推断与 WizTree 的整体速度差异。

## 宽目录内存汇总基准

运行 `cargo test --release --locked --bin filetree233 benchmark_wide_directory_finalization -- --ignored --nocapture`，生成 25 万个同级文件节点，仅计时内存中的树汇总。2026-11-02 Windows / Ryzen 9 9950X、Rust 1.99.1 本机三次观察：移除旧界面使用的同级排序前约 21–24 ms，移除后约 0.5–0.6 ms。该测试不包括生成节点、磁盘读取、导出或进程启动，不能据此推断全盘扫描速度或内存占用。

## MFT 并行读取的 CI 观察

Windows x64 和 ARM64 的真实 NTFS demo 测试对比 1 与 4 个扫描线程，校验完整树、大小、硬链接等结果一致；每轮最多暂存每个线程一个最多 1,024 条记录的分块，但单条记录名称和扩展属性长度不固定，且每个工作线程会占用读取缓冲及卷元数据，不能将其视为固定字节上限。

2026-11-02 GitHub Actions 的一次独立进程、热缓存测试：x64 为 18.91 / 18.80 秒，峰值工作集约 39.0 / 42.5 MB；ARM64 为 5.59 / 5.33 秒，峰值约 39.9 / 50.5 MB（前者为 1 线程，后者为 4 线程）。MFT 读取全卷，即使测试目录很小也依赖宿主卷；运行顺序固定，样本太少，不能据此声称稳定加速。线程越多不保证越快，且可能增加内存及随机 I/O。
